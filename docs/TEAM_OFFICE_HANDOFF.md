# SuperSUS: виртуальный офис — бета

## Публикация 2026-09-05

Пользователь поручил опубликовать вариант на сайте. Production-маршрут:
`https://supersussystem.com/?board=team&view=office`.
Presence API `/api/content/office-presence` проверяет существующую сессию
SuperSUS на чтение и запись, origin, участника по реестру, владение токеном,
размер/тип данных и частоту запросов. Эфемерные сессии живут в одном процессе
API, TTL 90 секунд, после перезапуска нужно войти в офис снова.

Пока действует самостоятельный выбор своего профиля среди участников команды,
а не отдельная идентификация каждого сотрудника. В интерфейсе обозначена бета.
Проверка протокола: `npm run test:office` (в том числе 401, чужая сессия,
дубликат входа, обмен статусами, TTL и лимит запросов).

## Задача

Встроить в `?board=team` игровой офис по визуальному направлению ролика
https://www.instagram.com/p/Dc5RRmLI9xG/ — объёмная сцена под углом,
персонажи сотрудников, персональные столы, перемещение и присутствие.
Существующие список команды и карта связей остаются доступными.

## Реализовано локально

- Режим «Офис», Three.js загружается отдельным чанком только при открытии.
- 16 рабочих мест; переговорная, зона отдыха, растения, мониторы.
- Источник сотрудников и проектов — существующие props TeamGraphBoard.
- При запуске с TEAM_OFFICE_PREVIEW=1 берётся read-only снимок текущей команды
  из единственного GET production API. Изменения в production не отправляются.
- Выбор персонажа, вход, выход, обход мебели, посадка у стола, поворот/зум камеры.
- Общие присутствие, координаты, статус и текст текущей задачи для вкладок,
  подключённых к одному локальному Vite-серверу. Обновление около 800 мс.
- Сессии только в памяти; при отсутствии heartbeat 20 секунд участник пропадает.
- Произвольный выбор сотрудника допустим только для локального прототипа.
- Нет скриншотов сотрудников, сбора клавиатуры или оценок продуктивности.

## Запуск

```sh
npm ci
TEAM_OFFICE_PREVIEW=1 npm run dev -- --host 127.0.0.1 --port 4196 --strictPort
```

Открыть http://127.0.0.1:4196/?board=team&view=office.
Для проверки синхронизации открыть две вкладки и выбрать разных персонажей.
Preview middleware существует только в Vite dev. Production использует
отдельный office-presence.mjs в существующем content API.

## До использования реальной командой

1. Собрать обратную связь по опубликованной бете.
2. Привязать вход к личной подтверждённой учётной записи, а не выбору имени.
3. Добавить восстановление сессии после обновления страницы и рестарта API.
4. Вынести сессию офиса выше режима отображения, если присутствие должно
   сохраняться при переходе в другие разделы SuperSUS.
5. Добавить поддержку более 16 мест/комнат, если состав команды увеличится.
6. Проверить background/сон устройства и UX при потере связи, затем развернуть.

Статус «Занят» и текст задачи задаёт сам человек; анимация не доказывает работу.
Автоматической оценки сотрудников в этом объёме нет.

## 2026-09-05: опубликованный демо-режим

Демо опубликовано через PR #55, merge `4f3521d2e2a11947fd0e5dc438d58873f4d60f5e`,
GitHub Actions `33968577977` успешно. На сайте проверены 16 персонажей и
переключение в реальный режим без фиктивных сессий.

- По согласованию добавлен включённый по умолчанию режим «Демо» с 16 персонажами.
- Переключатель возвращает реальное присутствие. Демо не обращается к presence API.
- Работа/обед меняются каждые 45 секунд, два персонажа гуляют по проходу;
  остальные отдыхают, лежат, спят или находятся в переговорке.
- Иванов: кальян рядом; Vasya: длинная борода; Gem: лысый, большие очки;
  Китаец: отдельная причёска. Это стилизованные персонажи, не портреты.
- Проверки: `node scripts/verify-office-demo.mjs`, `npm run test:office`, `npm run build`.
- В браузере проверены 16 демо-персонажей, переключение в реальный режим (0 онлайн),
  desktop-сцена; DOM на ширине 390 px без горизонтального переполнения.

## Следующий этап: расширение офиса (LOCAL, не опубликовано)

Согласованный объём: развёрнутый экран, фокус камеры, поиск/фильтры,
четыре быстрых действия, восстановление сессии, переподключение, пауза демо.

- `useOfficePresence` хранит токен офиса только в sessionStorage текущей вкладки.
  Серверный resume проверяет авторизацию и владельца токена. После refresh
  восстанавливаются имя, позиция, статус, занятие и последний отправленный текст.
- При закрытии вкладки присутствие исчезает по TTL 90 секунд. Перезагрузка
  в пределах TTL сохраняет сессию; после TTL/рестарта API нужен повторный вход.
  Персональная идентификация, persistence сервера и видеозвонки не добавлены.
- Запросы имеют timeout 8 секунд, отмену при смене режима и backoff до 30 секунд.
  При 401 не создаём участника заново автоматически. Демо по-прежнему не пишет API.
- За стол/на обед используют своё место, переговорка использует стулья у стола,
  отдых — передние кресла. Позы включаются после прибытия, не посреди прохода.
- Общий pathfinding вынесен в `officeLayout.js`; добавлена коллизия перегородки.
  Свободные места не бронируются: несколько реальных участников могут выбрать
  одну зону. Лимит сцены по-прежнему 16 рабочих мест.
- Демо гуляет по маршруту с остановками; пауза останавливает время анимации.
  Учитывается prefers-reduced-motion, имена при пересечении скрываются,
  выбранный сотрудник сохраняет подпись; полный список доступен справа.
- Фильтры действуют на список, не скрывают сотрудников из 3D-сцены.
- Проверено локально: вход Digitex, встреча, текст задачи, refresh и восстановление;
  сетевой offline в тестовой вкладке и возврат соединения; поиск Gem (1/16),
  фильтр offline в демо (0/16), сброс, пауза, развёрнутый режим, фокус камеры,
  ширина 390 px без переполнения. Сетевые/размерные overrides сняты.
- `npm run test:office` запускает проверки API, маршрутов, session cache и демо.
- Для публикации потребуется обычный frontend + content API деплой вместе:
  новые клиенты используют action=resume и activity, старый API их не поддерживает.
