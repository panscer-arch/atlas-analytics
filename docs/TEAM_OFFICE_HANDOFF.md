# SuperSUS: виртуальный офис — бета

## Публикация 2026-09-05

Пользователь поручил опубликовать вариант на сайте. Production-маршрут:
`https://supersussystem.com/?board=team&view=office`.
Presence API `/api/content/office-presence` проверяет существующую сессию
SuperSUS на чтение и запись, origin, участника по реестру, владение токеном,
размер/тип данных и частоту запросов. Эфемерные сессии живут в одном процессе
API, TTL 90 секунд, после перезапуска нужно войти в офис снова.

Пока действует самостоятельный выбор своего профиля среди участников команды,
а не отдельная идентификация каждого сотрудника. В интерфейсе обозначена бета.
Проверка протокола: `npm run test:office` (в том числе 401, чужая сессия,
дубликат входа, обмен статусами, TTL и лимит запросов).

## Задача

Встроить в `?board=team` игровой офис по визуальному направлению ролика
https://www.instagram.com/p/Dc5RRmLI9xG/ — объёмная сцена под углом,
персонажи сотрудников, персональные столы, перемещение и присутствие.
Существующие список команды и карта связей остаются доступными.

## Реализовано локально

- Режим «Офис», Three.js загружается отдельным чанком только при открытии.
- 16 рабочих мест; переговорная, зона отдыха, растения, мониторы.
- Источник сотрудников и проектов — существующие props TeamGraphBoard.
- При запуске с TEAM_OFFICE_PREVIEW=1 берётся read-only снимок текущей команды
  из единственного GET production API. Изменения в production не отправляются.
- Выбор персонажа, вход, выход, обход мебели, посадка у стола, поворот/зум камеры.
- Общие присутствие, координаты, статус и текст текущей задачи для вкладок,
  подключённых к одному локальному Vite-серверу. Обновление около 800 мс.
- Сессии только в памяти; при отсутствии heartbeat 20 секунд участник пропадает.
- Произвольный выбор сотрудника допустим только для локального прототипа.
- Нет скриншотов сотрудников, сбора клавиатуры или оценок продуктивности.

## Запуск

```sh
npm ci
TEAM_OFFICE_PREVIEW=1 npm run dev -- --host 127.0.0.1 --port 4196 --strictPort
```

Открыть http://127.0.0.1:4196/?board=team&view=office.
Для проверки синхронизации открыть две вкладки и выбрать разных персонажей.
Preview middleware существует только в Vite dev. Production использует
отдельный office-presence.mjs в существующем content API.

## До использования реальной командой

1. Собрать обратную связь по опубликованной бете.
2. Привязать вход к личной подтверждённой учётной записи, а не выбору имени.
3. Добавить восстановление сессии после обновления страницы и рестарта API.
4. Вынести сессию офиса выше режима отображения, если присутствие должно
   сохраняться при переходе в другие разделы SuperSUS.
5. Добавить поддержку более 16 мест/комнат, если состав команды увеличится.
6. Проверить background/сон устройства и UX при потере связи, затем развернуть.

Статус «Занят» и текст задачи задаёт сам человек; анимация не доказывает работу.
Автоматической оценки сотрудников в этом объёме нет.
