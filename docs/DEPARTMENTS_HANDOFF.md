# SuperSUS — «Отделы и процессы»

Дата: 6 сентября 2026. Статус: реализовано и проверено локально; на production не опубликовано.

## Согласованный объём

- Отдельная кнопка «Отделы» рядом с «Создай команду»; маршрут `?board=departments`.
- Три раздела: 7 отделов, 13 процессов, 11 предложений автоматизации.
- Предлагаемый состав определяется по текущим связям проектов в реестре команды. Имена отображаются по ID из актуального ответа сервера. Это не утверждённые назначения и не оценка загрузки сотрудников.
- Руководители по умолчанию не назначены; все автоматизации имеют статус «Нужна проверка».
- Редактор: названия, описание, участники/проекты отдела, ответственный, статус, следующие шаги, заметки. Добавление карточек, поиск, фильтры, JSON-экспорт.
- Автоматизация «Работает» требует ответственного и текстового подтверждения проверки. Эта отметка вводится редактором и не является автоматической технической сертификацией.
- Подробности: ограничения AI, ручной резерв, предложения по данным/инструментам; сами интеграции не запускаются.

## Данные и безопасность

- `supersus.teamGraph.v3` — только чтение. Старые назначения, граф, офис и presence не менялись.
- `supersus.departments.v1` — отдельная запись через существующий content API.
- При первом открытии показывается предложение; без нажатия «Сохранить» запись на сервер не выполняется.
- Ошибка первоначальной загрузки блокирует редактирование и запись. Неверная схема не заменяется seed-данными.
- Сохранение: чтение текущей версии → сравнение со снимком → PUT → чтение и проверка сохранённого результата.
- Это не атомарный CAS: существующий API для нового ключа не имеет revision lock. Одновременное редактирование двумя людьми не гарантируется; использовать одного редактора за раз. Для полноценной совместной работы потребуется серверная проверка ревизий.
- Несохранённые правки резервируются в sessionStorage; после перезагрузки предлагается явное восстановление. Есть экспорт в JSON.
- Обновление имён в команде отражается при новой загрузке. Состав уже сохранённых отделов не пересоздаётся автоматически при изменении проектов; редактируется отдельно.
- Чтение и запись нового ключа защищены существующей сессией SuperSUS; без авторизации API возвращает 401. Для записи проверяется Origin при его наличии; cross-origin запрос отклоняется. В интерфейсе есть вход с действующим паролем SuperSUS. Персональные роли редакторов не добавлялись. Не хранить здесь пароли, ключи или персональные финансовые данные.

## Локальная версия

Код: `/tmp/sus-team-office-20260905` (существующий worktree; исходный HEAD `b0ef226`).

Приложение: `http://127.0.0.1:4198/?board=departments`.

API: `http://127.0.0.1:8797`. Данные: `outputs/departments-preview-store` внутри worktree. Это отдельное локальное хранилище; production-записей не было. Оно заполнено снимком 16 участников/22 проектов с production GET и предложением структуры.

Запуск API:

```sh
ATLAS_CONTENT_API_PORT=8797 ATLAS_CONTENT_STORE_DIR=/tmp/sus-team-office-20260905/outputs/departments-preview-store node server/content-api.mjs
```

Запуск UI:

```sh
VITE_DEV_CONTENT_API_TARGET=http://127.0.0.1:8797 npm run dev -- --host 127.0.0.1 --port 4198 --strictPort
```

Не использовать `TEAM_OFFICE_PREVIEW=1` для редактируемого просмотра: этот существующий режим блокирует PUT и предназначен для read-only QA офиса.

## Проверка

- `npm run test:departments` включает модель и изолированный тест реального API: анонимный доступ запрещён, авторизованная запись/чтение работают, cross-origin запись запрещена, старый ключ команды не затронут. Тест добавлен в production CI.

- `node scripts/verify-departments.mjs`: изоляция seed от команды, реальные ID участников, исходные статусы, валидация, фильтрация, отказ при ошибке чтения, конфликт, проверка результата записи.
- `scripts/check-departments.mjs`: реальный React UI с подменой внешнего API на тестовой границе. Маршрут, переключение, Back, добавление процесса, редактор, сохранение/перезагрузка, пустой поиск, ограничения статусов, отказ записи при потере связи, восстановление черновика, мобильная ширина, отсутствие runtime ошибок.
- Отдельно без подмены API проверены полная команда, запись и повторное чтение через локальный content API, перезагрузка, 11 автоматизаций и мобильный экран.
- `npm run test:office` — PASS; существующий офис не регрессировал по его автоматическим тестам.
- `npm run build` — PASS. Остались предупреждения существующей сборки: крупный bundle и использование eval библиотекой lottie-web.
- `git diff --check` — PASS.

## Перед публикацией

1. Получить отдельное согласование публикации, сверить актуальную production-ветку; не выкатывать старый worktree поверх новых изменений.
2. Перенести только новую вкладку и четыре изменения навигации; чужую правку `docs/TEAM_OFFICE_HANDOFF.md` не включать.
3. Проверить защиту API и решить, достаточен ли режим одного редактора.
4. После публикации проверить маршрут, редактор, запись/повторное чтение и неизменность ключа команды.
5. Начальную структуру сохранить явно после просмотра; не выдавать её за утверждённую оргструктуру.
